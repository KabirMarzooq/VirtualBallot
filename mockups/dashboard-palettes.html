Admin dashboard — palette options

Same layout, same information, four different colour treatments.

For approval — nothing implemented. The thing reading as "vibe coded" is almost certainly A: a near-black navy sidebar with a saturated blue-600 active state. That exact pairing is the default look of nearly every AI-generated admin template, which is why it feels generic even though nothing is technically wrong with it. Each option below changes only the chrome — sidebar, accent and surface tints. Layout, spacing and type stay identical, so whichever you pick is a token swap, not a rebuild.

A · Navy & Blue

Current

What's live today. The sidebar and the accent are both blue, so the active nav item doesn't separate from its background, and the whole console reads as one saturated block. This is the pairing to move away from.

B · Ink & Clay

Warm near-black sidebar with a terracotta accent. The warm neutrals immediately break the cool-navy template look, and because the accent is used sparingly the data stays the loudest thing on screen. Active nav is a raised warm charcoal rather than a colour fill, so it reads as depth instead of highlight.

C · Paper & Ink

Recommended

Drops the dark sidebar entirely. A white rail separated by a hairline, near-black type, and a light grey active state — no accent colour in the chrome at all. This is the furthest from the AI-template look, it makes the console feel like an instrument rather than a product landing page, and it lets the semantic colours you already use (green approved, amber pending, red danger) carry real meaning because nothing else is competing. It also solves a real problem: the dark rail currently forces a hard seam against the light content, which is what makes the tabs look "stuck on".

D · Oxford Green

Deep green with a muted brass accent — an institutional, electoral-commission register. The most distinctive of the four and the best fit if you want the product to feel official rather than start-up. The trade-off is that it is a strong opinion, and green already carries "approved" meaning elsewhere in the UI, so the chrome and the status colours would need care not to collide.

Scope of changeSidebar background, active-nav treatment, accent, canvas tint and border greys. Roughly 20 token values — no layout or spacing changes anywhere.
Blue elsewhereB, C and D all reduce or remove blue from the chrome. Blue stays as the primary action colour on buttons and links across the rest of the product, so the auth screens and voter-facing pages are unaffected.
Status coloursGreen/amber/red keep their current meanings in every option. D is the one to watch, since its chrome green sits near the "approved" green.
ContrastEvery sidebar/label pairing above clears 4.5:1 for body text and 3:1 for the muted group labels. C has the highest text contrast of the four.
If you pick oneI'd apply it to Admin, Observer, SuperAdmin and the staff console together, since they share the shell — doing one alone would look like a bug.
